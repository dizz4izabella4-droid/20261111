# 音声ツール（VOICE）設計書

対象: `tools/voice.html`（本体）、`tools/voice-test.html`（試験ページ）、`tools/voice-align/`（AI 側の切り分けスクリプト）
元の指示書: `tools/voice-plan-v5.md`（v5 をそのまま複製）。本書の決定は指示書より優先する（ユーザー決定 A–G を反映）。

## 1. 全体の流れ（決定 A）

```
 ┌───────────── tools/voice.html（ブラウザ・単一HTML・通信なし）─────────────┐
 │ ① 台本: 例文16本を表示 → 録音 or 取り込み（1本＝1録音）                  │
 │    不足音の一覧 → 「不足音を1つずつ録る」録音                             │
 │ ② 「切り分け依頼」を書き出す  ──►  <名前>.cutreq.zip                     │
 └──────────────────────────────────────────────────┬───────────────────────┘
                                                    │（ユーザーが Claude Code に渡す）
                       tools/voice-align/align.py   ▼
                       Julius 強制アラインメント（無ければ信号解析）
                                                    │
                                     labels.json ◄──┘
 ┌──────────────────────────────────────────────────┴───────────────────────┐
 │ ③ labels.json を読み込む → 波形にかなを描画、低信頼は橙色               │
 │ ④ 聞いて、境界をドラッグで直す（AIなしでも 無音分割／均等割り／手で引く）│
 │ ⑤ 素材: 音ごとに複数テイク → 基準の高さに最も近いものを自動選択（手で変更可）│
 │ ⑥ 話す: テキスト → 読み → 音節 → つなぐ → 再生                         │
 │ ⑦ 台帳 → 書き出しパックA（voice.wav / voice.json / voice-player.js）     │
 │ 保存: 1ファイル .voiceproj（＋IndexedDB 自動退避）                       │
 └──────────────────────────────────────────────────────────────────────────┘
```

AI（Claude Code）の手順は `tools/voice-align/README.md` に書いた。1 コマンドで終わる:
`python3 tools/voice-align/align.py <file>.cutreq.zip -o labels.json`

## 2. 音節（モーラ）の一覧 — 101 個

| 区分 | 数 | 中身 |
|---|---|---|
| 清音 | 45 | あ〜ろ（40）＋ や ゆ よ ＋ わ ＋ ん。**を は お**（決定 E） |
| 濁音・半濁音 | 23 | が ざ だ ば 行 18（**ぢ→じ、づ→ず**）＋ ぱ行 5 |
| 拗音 | 33 | き し ち に ひ み り ぎ じ び ぴ × ゃゅょ（**ぢゃ行は じゃ行**） |

- 「同じ音」とみなす置換: を→お、ぢ→じ、づ→ず、ぢゃ/ぢゅ/ぢょ→じゃ/じゅ/じょ、ゐ→い、ゑ→え、ゎ→わ。
- 外来音（ふぁ てぃ でぃ など 27 個）は「任意」。録れば使い、無ければ不足（赤）として扱う。カバー率の分母には入れない。
- 録らないもの: っ（無音で作る）、ー（直前を伸ばす）。
- 長音のひらがな表記（おう、えい）は特別扱いしない（決定 D）。「おう」は お＋う の2音。不自然な語は定型句で録る。

この表は `voice.html` の `INVENTORY` と `tools/voice-align/kana.py` の `INVENTORY` の2か所にある。`tests/check_sync.py` が一致を確かめる。

## 3. 例文（決定 A の「短い例文で全音をカバー」）

`tools/voice-align/sentences.json`（`voice.html` に同じものを埋め込み）。16 文・279 音節で 101 音すべてを含む。
助詞は発音どおり（わ・え・お）に、かなで書いてある。何回出てくるかを画面に出し、1回しか出ない音（50 個）は「予備のテイクが無い」と分かるようにする。

不足音: 例文の録音を切り分けたあと、ラベルの無い音を赤で並べる。「不足音を1つずつ録る」で、その音だけを間を空けて読む録音を作る（期待列＝不足音の並び）。この録音は無音分割だけで切れる。

## 4. ファイル形式

### 4-1 切り分け依頼 `<名前>.cutreq.zip`（アプリ → AI）

無圧縮 ZIP。中身:
- `request.json`
- `<recId>.wav` … モノラル 16bit PCM、録音時のサンプルレートのまま
- `README.txt` … AI 向けの1行手順

```json
{ "format": "voice-cutreq", "version": 1,
  "requestId": "req-20261125-2140", "project": "わたしの声",
  "created": "2026-11-25T21:40:00+09:00",
  "recordings": [
    { "recId": "r-lq2x8k", "file": "r-lq2x8k.wav", "sampleRate": 48000, "duration": 3.84,
      "crc32": "1a2b3c4d", "text": "客が急に教会へ走る", "kana": "きゃくが きゅうに きょうかいえ はしる",
      "expected": ["きゃ","く","が","きゅ","う","に","きょ","う","か","い","え","は","し","る"] } ] }
```

- `expected` は話す順の音節列。っ・ー も1要素として入る（ラベルは付くが素材にはしない）。読点や空白は入らない（間の位置は AI 側が自分で見つける）。
- `crc32` は WAV ファイルのバイト列の CRC32。labels.json 取り込み時に「別の音声に対するラベルではないか」を確かめる。

### 4-2 ラベル `labels.json`（AI → アプリ）

```json
{ "format": "voice-labels", "version": 1, "generator": "voice-align/1.0",
  "created": "2026-11-25T21:45:00+09:00", "request": "req-20261125-2140",
  "recordings": [
    { "recId": "r-lq2x8k", "crc32": "1a2b3c4d", "method": "julius", "duration": 3.84,
      "labels": [ { "i": 0, "kana": "きゃ", "start": 0.512, "end": 0.701, "confidence": 0.82 } ],
      "warnings": [] } ] }
```

- 時刻は秒（元の WAV の先頭から）。`start < end`。ラベル間に隙間があってよい（読点の間など）。重なりは作らない。
- `confidence` は 0〜1。アプリは「設定の低信頼しきい値（既定 0.5）」未満を橙色で目立たせる。手で直したラベルは `confidence` を消して「確認済み」扱い。
- `method`: `julius` / `signal` / `signal-silence`（無音分割で数が合った）。
- アプリは `recId` で照合し、`crc32` 不一致・数の不一致を警告するが、取り込みは行う。
- 一つの録音だけの形 `{ "recId":…, "labels":[…] }` も受け付ける（手で作るとき用）。

### 4-3 プロジェクト `.voiceproj`（決定 C）

無圧縮 ZIP（拡張子だけ変えたもの。展開すれば中身が見える）。
```
project.json         … 下記
audio/<recId>.wav    … 各録音（モノラル 16bit、録音時のレート）
```
```json
{ "format": "voiceproj", "version": 1, "name": "わたしの声",
  "createdAt": "…", "updatedAt": "…",
  "settings": { "refHz": null, "crossfadeMs": 12, "speed": 1, "gapMs": 0, "gain": 1,
                "sokuonMs": 70, "choonMs": 160, "pauseComma": 180, "pausePeriod": 350, "pauseQ": 350,
                "targetRms": 0.12, "peakMax": 0.6, "fadeMs": 3, "hpHz": 80, "gateDb": -50,
                "lowConfidence": 0.5, "pitchTolCents": 150, "exportRate": 24000,
                "silThresholdDb": -35, "silMinMs": 120, "segMinMs": 60 },
  "recordings": [ { "id": "r-lq2x8k", "name": "s01 客が急に…", "kind": "sentence",
                    "sentenceId": "s01", "text": "…", "kana": "…", "expected": ["…"],
                    "sampleRate": 48000, "length": 184320, "crc32": "…", "createdAt": "…",
                    "labels": [ { "kana": "きゃ", "start": 0.512, "end": 0.701,
                                  "confidence": 0.82, "src": "ai" } ],
                    "labelsFrom": { "generator": "voice-align/1.0", "method": "julius", "at": "…" } } ],
  "picks": { "か": "r-lq2x8k#8" },
  "lines": [ { "id": "greet.1", "text": "こんにちは", "exportedHash": "9f1c0a22" } ],
  "dictionary": { "暗算": "あんざん" } }
```
- `kind`: `sentence`（例文）/ `single`（不足音を1つずつ）/ `phrase`（定型句）/ `free`（取り込んだ任意の音声）。
- 定型句は `kind:"phrase"` の録音そのもの。`text` と `kana` と `hash`（録音時の文の FNV-1a）を持ち、ラベルは全体1個（kana＝読み全体）。文を直すと hash が変わり「差替待ち」になる。別の配列は持たない。
- `picks` は手で選んだテイクだけ（`録音id#ラベル番号`）。無い音は自動選択。
- `lines` は書き出しパックAの台帳。`exportedHash` は前回書き出した時点の文の hash。文が変わると「差替待ち」。

保存: File System Access API があれば（Chrome/Edge、https か localhost）`showSaveFilePicker` で選んだファイルに上書き保存。無ければダウンロード／ファイル選択で開く。どちらでも IndexedDB に自動退避（変更後 1.5 秒、録音中は 1 秒ごとに録音の断片）。

### 4-4 書き出しパック A（指示書 §6-1 のまま `format:1`）

`voice.wav`（モノラル 24kHz 16bit、行の間に 0.1 秒の無音）、`voice.json`、`voice-player.js`（§6-2 の再生コード）。File System Access のフォルダ選択があればフォルダへ直接、無ければ ZIP をダウンロード。読みが決まらない行・素材が足りない行は書き出さず、一覧で知らせる。

### 5-1 方式の選択と結果

**採用: Julius 強制アラインメント（segmentation-kit のモノフォンモデル）**。各音節を1「単語」にした直線の文法（silB → 音節… → silE、各音節の後ろに省略可能な `sp`）を作り、`-palign` の音素境界から音節の始まり（子音の始まり）と終わり（母音の終わり、`sp` は含めない）を取る。信頼度は Julius の単語信頼度 `cmscore1`×（長さが 35〜450ms か）×（音素の平均尤度）。Julius が失敗した録音だけ信号解析に回し、警告を付ける。

**予備: 信号解析**（numpy のみ）。10ms ごとの帯域エネルギー・高域比・エネルギーの谷から「次の音節の頭子音の種類」（破裂・摩擦・鼻音・流音・半母音・母音）別の境界らしさを出し、期待の音節数で区切る動的計画法（長さの事前分布つき）で最適な境界を求める。信頼度は前向き後ろ向き計算での境界の事後確率（±20ms）。無音で区切って数が合えばそれを使う（不足音の録音向け）。

両方とも最後に、ラベルの端に入った無音を 10ms だけ残して詰める（指示書 §3-2 の「頭 5ms・尻 10ms」相当）。

**精度（合成音声での実測）** — 境界誤差＝ラベルの始まり・終わりそれぞれと正解の差の絶対値。

| 条件 | 方式 | 中央値 | 平均 | 90% | ≤20ms | ≤50ms | 50ms超のラベル |
|---|---|---|---|---|---|---|---|
| kyoko-clean（48kHz、つなぎ 8ms、語の間 60ms、雑音 -60dB） | julius | 6.5 | 7.8 | 17.3 | 95.6% | 100% | 0 / 281 |
| 同 | signal | 10.4 | 36.4 | 122.3 | 69.2% | 76.5% | 89 / 281 |
| kyoko-tight（つなぎ 25ms、尻 15% 切り、間なし、-50dB） | julius | 8.8 | 10.0 | 20.1 | 89.7% | 100% | 0 / 281 |
| 同 | signal | 6.0 | 17.9 | 66.8 | 80.4% | 83.3% | 71 / 281 |
| flo-tight（別の声、44.1kHz） | julius | 10.7 | 13.4 | 26.8 | 75.1% | 99.6% | 2 / 281 |
| 同 | signal | 6.0 | 13.8 | 35.8 | 86.1% | 93.2% | 36 / 281 |
| kyoko-singles（12音を間を空けて） | julius | 14.3 | 14.5 | 21.2 | 83.3% | 100% | 0 / 12 |
| 同 | signal-silence | 15.3 | 14.7 | 23.7 | 70.8% | 100% | 0 / 12 |

単位は ms。全 16 文 × 4 条件で音節数の不一致は 0。端を 10ms 残す処理のため、正解より平均 2〜10ms 外側に出る（意図どおり）。

**この数字の限界**: 合成音声は「1音ずつ読み上げた音をつないだもの」で、音節どうしの音の渡り（調音結合）が無い。本物の朗読では境界があいまいになるので、誤差はこれより大きくなる見込み。実際の声での精度は未測定。だから低信頼の表示と手直しの画面を必ず通す流れにしてある。

## 6. アプリの構成（`tools/voice.html`、単一HTML・外部ライブラリなし・通信なし）

1 つの `<script>` の中を名前空間で分ける。試験ページから `iframe.contentWindow.VoiceCore` で中身を呼べる。

| 名前 | 役割 |
|---|---|
| `Kana` | 一覧・置換・カタカナ→ひらがな・音節分解・カバー率 |
| `Reading` | テキスト→読み（`漢字{よみ}`、`[よみ]`、辞書の最長一致、数字、記号の間）。読めない文字は `unresolved` |
| `DSP` | WAV 読み書き、リサンプル（窓付き sinc）、高さ（YIN）、RMS、高域通過、ゲート、フェード、ピーク・帯域の測定 |
| `Zip` | CRC32、無圧縮 ZIP の書き出し、読み込み（deflate は `DecompressionStream` があれば） |
| `Store` | IndexedDB（プロジェクト退避、録音の断片） |
| `Project` | データ構造、保存・読み込み、ラベル取り込み、切り分け依頼の書き出し |
| `Bank` | テイクの一覧、高さの測定、自動選択、素材の加工（キャッシュ付き） |
| `Synth` | 並べる計画（定型句の最長一致 → 音節）、連結、タイムライン |
| `Pack` | 書き出しパック A、容量の見積もり、`PLAYER_SRC`（再生コードの原本） |
| `Rec` | MediaRecorder、レベル・高さ表示、断片の退避と復元 |
| `Editor` | 波形と区切りの編集（Canvas、ポインタ操作。iPhone のタッチも同じ処理） |
| `UI` | 画面（台本・切り分け・素材・話す・台帳と書き出し・保存と設定） |

### 6-1 読み（指示書 §3-4 の具体化）
- かな（ひらがな・カタカナ）はそのまま。カタカナの ー は長音。
- `漢字{よみ}`: `{}` の直前の「かな以外の連続」に読みを付ける。直前がかなの場合はその1文字（例 `は{わ}`）。付けた読みは辞書に自動登録（設定で切れる）。
- `[よみ]`: 書いたかなをそのまま読みに入れる（表示上の文字は無い）。助詞は `わたし[わ]` のように書くか `は{わ}`。
- 辞書: 文中の文字列に対して最長一致で当てる（かなでない部分のみ）。
- 数字: 0〜99,999,999、小数（てん＋1桁ずつ）、`%`（ぱーせんと）、桁区切りの `,`。音便（さんびゃく、ろっぴゃく、はっぴゃく、さんぜん、はっせん、いっせんは「せん」）。それより大きい数は読めない扱い。
- 間: 、→180ms ／ 。？！→350ms（設定で変更）。空白は間なし。
- それ以外（英字・読みの無い漢字）は赤で表示し、話さない。

### 6-2 合成（指示書 §3-5 の具体化）
- 素材: テイクの区間を切り出し → 高域通過 80Hz → ゲート（-50dB 以下を 5ms 単位でなめらかに下げる）→ 有声部分の RMS を 0.12 にそろえ、ピークが 0.6 を超えるなら下げる（クリップはしない）→ 頭・尻に 3ms フェード → 48kHz に。
- 連結: 前の素材の尻と次の素材の頭を `crossfadeMs`（既定 12ms）重ねる（等パワー）。出力長＝Σ素材長 −（つなぎ数）×重なり。
- 速さ: 1 より速い→重なりを増やす（素材長の 40% まで）。1 より遅い→素材の後半（母音）をくり返して伸ばす。高さは変えない。
- っ: 直前の素材の尻 20% を切って（5ms フェード）、`sokuonMs` の無音。
- ー: 直前の素材の 55〜90% の部分をくり返して `choonMs` 伸ばす。
- 音節間の間 `gapMs` > 0 のときは重ねずに無音を入れる。
- 定型句の最長一致を先に当て、残りを音節で埋める。
- 素材が無い音節: 赤で表示し、再生はその音節を飛ばし（無音を入れない）、画面に警告を出す。
- 最後に全体のゲインをかけ、ピークが `peakMax×gain` を超えたら全体を下げる。

### 6-3 テイクの自動選択（決定 A）
基準の高さ＝設定の Hz（空なら全テイクの高さの中央値）。各テイクの高さ（YIN、有声フレームの中央値）との差（セント）が最小のものを選ぶ。高さが測れないテイク（無声化した し・く など）は後回し。同点なら信頼度の高い方、手で直したラベルを優先。手で選んだテイク（`picks`）が最優先。基準から `pitchTolCents`（既定 150）以上ずれたら警告。

## 7. 指示書の問題点と対応

| # | 指示書の箇所 | 問題 | 対応 |
|---|---|---|---|
| 1 | §3-1 清音46 | を を除くと 45。ぢ・づ は じ・ず と同じ音なのに数に入っている（濁音20） | 101 音（45＋18＋5＋33）。ぢ・づ は置換 |
| 2 | §3-1 単独音 | 決定 A で例文の朗読に変更。単独音は不足音だけ | 例文16本＋不足音の録音 |
| 3 | §3-1 / 決定 A | 朗読から切った音節は前後の音の渡りやアクセントの高さを含む | 複数テイクから基準の高さに近いものを選ぶ。手で選べる。不自然なら定型句 |
| 4 | §3-2 無音検出で自動分割 | 文の朗読は音節の間に無音が無いので、無音検出では切れない | 主は AI。手動用に「均等割り」を足した。無音分割は不足音の録音向け |
| 5 | §3-3 RMS そろえ と ピーク≤0.6 | 両立しない素材がある | RMS をそろえたあとピークで下げる（その素材は少し小さくなる） |
| 6 | §3-3 / §9 ピーク≤0.6 | 連結の重なりで和が 0.6 を超えうる | 出力の最後にピークで全体を下げる |
| 7 | §3-4 `[わ]` | 書き方の規則が無い（どこに書くか） | `[よみ]` は「その位置に読みを入れる」、`X{よみ}` は「直前に読みを付ける」 |
| 8 | §3-4 数字 0〜99,999 | 音便の規則が書かれていない | 6-1 の規則。上限は 1億未満に広げた（数値は既定扱い・決定 G） |
