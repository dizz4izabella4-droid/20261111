## 1. 依頼の趣旨と前提（ユーザーの指示）

- 作りたいもの: **Procedural Modeling（プロシージャルモデリング）形状自動生成アプリ**。要件は4つ。
  1. 数値・規則による3D形状生成
  2. パーツの自動配置・反復生成
  3. パラメータ変更による形状再構築
  4. テンプレートによるモデル生成
- **テクスチャは別アプリで重ねる**。このアプリは、テクスチャを貼る前の**ポリゴン素体**づくりに特化する。色は仮のもの。
- **ポリゴン数は気にしない**（今のスマートフォンは性能が高い）。軽量化より表現を優先する。
- **PCが主な想定**。ただしスマホにも対応する。
- 今のテーマは**廃墟**。破損部分などが単調にならない組み上げ方法を考えて実装してほしい、という依頼で進めた。
- **毎回、作ったHTMLをファイルとして出力する**（公開ページの更新に加えて、HTMLファイルも渡す）。
- コード冒頭のコメントに、制作者クレジット（「dizz が制作した作品です」）を入れている。消さない。
- 返答は日本語。

## 4. コードの構造（procedural.html の中身）

1ファイル完結。`<script>` の中に、おおよそ次の順で並んでいる（関数名や定数名で検索すれば見つかる）。

### 4-1. データの流れ
```
テンプレート T[ti].g(v, R, o)   →  Part の配列 o
        ↓
mods(o)  … モディファイアスタック MS を上から順に適用（配列/放射/植生/破損/段積み/グリッド/ミラー/散布）
        ↓
post(o)  … 全体スライダー（ねじり・先細り・ゆらぎ・放射コピー・大きさ）
        ↓
上限 MAXP(25万) で打ち切り → LAST に保存（OBJ書き出し用）
        ↓
形状の種類ごとに InstancedMesh へまとめて描画
```

### 4-2. 基本のデータ型
- **Part** = `{ g: 'box'|'cyl'|'sph'|'cone'|'lathe', m: THREE.Matrix4, c: THREE.Color }`
- 追加ヘルパー:
  - `P(out, g, pos[3], rot[3](Euler XYZ), scale[3], color)`
  - `Pq(out, g, Vector3, Quaternion, scale[3], color)`
  - `bx(o, pos, size, color?)`（箱）
  - `hsl(h,s,l)`（色）、`Z=[0,0,0]`、`O=[1,1,1]`
  - `Op.array / Op.radial / Op.scatter`（配置オペレータ）
- `GEO` = 共有ジオメトリ（box 1×1×1、cyl 半径0.5・高さ1・14分割、sph 半径0.5、cone）。`GEO.lathe` は、回転体テンプレートが生成のたびに作り直す（1個だけ）。
- 乱数: `rng(seed)`（シード固定で再現可能）。テンプレートの `R` はこれ。

### 4-3. テンプレートの書式
```js
{ n: '名前',
  p: { キー: ['ラベル', 最小, 最大, 初期値, 刻み], ... },   // これだけでスライダーUIが自動生成される
  g(v, R, o) { /* v=現在値, R=乱数, o=出力するPart配列 */ } }
```
- 配列 `T` に並べる。画面の左（スマホは上）の一覧は、`T` の順に自動で作られる。
- 他のテンプレートを部品として呼ぶ: `sub(名前, 上書き値, x, z, 回転Y, salt, o)`（廃墟の街区が使用）。
- 破損の処理は `dmg(o, {rate, sc, ero, tilt, rub, dir}, salt)`、植生は `veg(o, {vine, len, grass, moss}, salt)`。テンプレートの中から直接呼んでよい。
- `DSALT` は `sub` 経由で呼ぶときの乱数のずらし幅（呼び出しごとに壊れ方を変えるため）。

### 4-4. モディファイア
- 定義は `MD = { キー: { n:'表示名', p:[[ラベル,最小,最大,初期,刻み],...] } }`。
- 状態は `MS = [{ t:キー, v:[値...] }, ...]`。適用は `mods(o)` の中の分岐。
- **項目を足すときは、配列の末尾に足す**。古い保存データは、足りない項目を初期値で補うため（`normMS`）。

### 4-5. 状態の保存・復元
保存する状態: テンプレート番号 `ti`、現在値 `V`、シード `seed`、色相 `hue`、L-systemルール文、断面 `PF`、モディファイア `MS`。
**保存対象に新しい状態を足すときは、次の5か所を同時に直す**:
`snap()` / `restore()` / ギャラリー保存（`gal.push`）/ JSON表示（`jshow`）/ JSON読み込み（`jload`）。
- 全体スライダーの値は `V.g_twist` `V.g_taper` `V.g_noise` `V.g_copies` `V.g_scale` に入っている（`post()` が読む）。

### 4-6. 描画・UI
- 描画は、変化があったときだけ（`dirty` フラグとカメラ値の比較）。スライダー操作の再生成は `sched()` で、1フレームにつき1回までに絞る。
- カメラは自前の簡易オービット（`az`, `el`, `dist`, `tgt`）。OrbitControls は使っていない（r128 で使えないため）。
- 表示設定: `flat`（ローポリ/滑らか）、`mono`（素体グレー）、`shad`（影）、`lit`（光:昼/夕/夜）、`wire`。保存対象には**入っていない**。
- スマホ用の画面は、CSS の `@media(max-width:760px)`（3D表示を上部に固定）。
- L-system: `lsys()`（文字列の置換）と `turtle()`（3D描画）。見た目の係数は `LO`（花・葉の大きさ、太さの減り、幹の太さ、色相）。ルール文の書式は説明書の8章。

## 5. 変更のしかたと確認手順

### 5-1. よくある変更の型
- **テンプレートを足す**: `T` の中（たとえば `{n:"橋"` の直前）に、4-3の書式で足す。
- **モディファイアを足す**: `MD` に定義を足し、`mods()` に分岐を足す。
- **全体スライダーを足す**: `defaults()` の `V` の初期値、`ui()` の `add(...)`、`post()` の処理、の3か所。
- **保存対象を足す**: 4-5の5か所。

### 5-2. 構文チェック（node が使える環境で）
```bash
python3 - <<'PY'
import re
s=open('procedural.html',encoding='utf-8').read()
open('/tmp/p.js','w',encoding='utf-8').write(re.findall(r'<script>(.*?)</script>',s,re.S)[-1])
PY
node --check /tmp/p.js && echo SYNTAX_OK
```
これは**構文の確認だけ**。画面での見た目や動作は確認できない。three.js が手元に無い環境（ネット無し）では、生成関数を実際に動かす試験もできていない。

### 5-3. 文字列置換（edit）のコツ
- old_str は、現在のファイルの文字列と一致させる（空白・改行・引用符の種類まで）。
- 日本語を含む文字列は、ファイル内で二重引用符のものと単一引用符のものが混在している（古いコードは二重、新しく足したものは単一が多い）。直す前に、該当行を確認する。

## 8. 既知の制約・未検証

- **画面での動作確認は未実施**（構文チェックと、参照名の存在確認のみ）。再開時は、まずブラウザで開いて、テンプレートを一通り切り替えて確認するのが安全。
- 各部品は、パーツの重ね合わせで作っており、1枚につながったメッシュではない（めり込み、内側の面が残る）。OBJ書き出しでも、頂点の溶接や内側の面の除去はしない。
- 屋根は2枚の板のみ（妻側なし）。蔓は、壁の形によって、めり込みや浮きが出ることがある。
- 概寸は、パーツの中心位置から求めた目安で、実際よりやや小さく出る。
- 「戻す」「ギャラリー」「JSON」に、表示設定（影・光・素体など）は含まれない。ギャラリーに入るのは、テンプレート・シード・現在値・色相・L-systemルール・断面・モディファイア。
- 公開ページ（claude.ai上）の中では、ファイル保存（OBJ書き出し）が効かないことがある。HTMLファイルをブラウザで直接開けば使える。
- ギャラリーは localStorage 保存（そのブラウザだけ）。

## 9. 次の候補（優先度の目安）

1. **ファイル分割**: 生成の中核、テンプレート、画面を別ファイルに分ける（改修コストを下げる。会話で合意済みの方向）。

3. 廃墟の続き: 建物の向きの変化、街区の路面、廃墟の建物への屋根崩落・階段・配管の組み込み、破損と植生のプリセット保存。
4. 断面を、円以外（四角・星形）の輪郭にも使えるようにする。
5. ノードグラフUI（第2版の本命）。今はモディファイアの縦積みで代用している。
6. OBJ のUVを、実寸ベース（1mあたりの繰り返し）にそろえる。別アプリのテクスチャ貼りを楽にするため。

### 自動化の検討メモ（会話での結論）
- AIに画面を操作させるより、**AIは設定JSONだけ決め、生成と検品はスクリプトで自動化**するのが低コスト。
- 検品は層に分ける: ①数値で自動検品（ほぼ無料）→ ②重複排除 → ③サムネ一覧を人が見る → ④採用品だけ詳細確認。感覚的な基準（廃墟らしさ、単調さ）は、最終的に人が見る部分として残る。
- 統合すると改修コストは上がる。別チャットになると文脈が消えるため、構造を分ける・JSONを共通の約束にする・引き継ぎメモ（この資料）を置く、が対策。

## 10. テクスチャのサンプル（参考）

- 提供された `ビル.zip` の中身: `画像 27/` の `_albedo` `_normal` `_orm` `_height`（各 1536×1024）、`material.json`、`viewer.html`。
- `_orm` は R=AO、G=粗さ、B=金属感として扱った。height は使っていない。
- サンプルでは画像を 1024×683 に縮小して、HTMLの中に埋め込んだ。貼り付けの本番は別アプリの仕事で、このアプリは素体（OBJ）を渡す側。
