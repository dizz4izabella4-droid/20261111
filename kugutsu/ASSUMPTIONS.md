# ASSUMPTIONS（判断の記録）

書式：日付｜項目｜判断｜理由

- 2026-11-26｜アプリの分離｜動く素体（body-motion）から、動きの部分を「傀儡」として分けた。体はスペアボディの GLB を読み込む（スペアボディのコードは持たない）｜ユーザーの指示。体とのやりとりをファイルにしておけば、どちらも単独で開発できる。
- 2026-11-26｜読み込む体｜骨格つき GLB（スキンメッシュ）。骨の名前でつなぐ（hips, spine, chest, neck, head, upperarm_l, forearm_l, hand_l, thigh_l, shin_l, foot_l と _r、任意で toe_l/toe_r）。足りない骨はその部分を動かさず、画面に表示する。読み込んだときの姿勢（バインドポーズ）を立ち姿とする｜スペアボディ以外の GLB でも、同じ名前の骨があれば動くように。
- 2026-11-26｜動きの当て方｜「モーション」の JSON（dizz-mocap-v1）の 33 点の関節位置から、立ち姿からの回転（ワールド空間）を求め、最終の回転＝その回転×立ち姿の回転として当てる（立ち姿の骨に回転があっても動く）。腰・胸は肩と腰の線と背骨、背骨・首は中間、頭は耳の線、腕・脚・足は親に対していちばん小さい回転で向きを合わせる。腰と胸は体の立ち姿の線を基準にする（立ち姿と同じ姿勢＝回転なし）。手は手首→人差し指と小指の付け根の中点、足は足首→つま先（体のつま先の骨に合わせる）。移動（root）があれば腰を最初のフレームからの差だけ動かす。ねじれ・うなずきは関節位置から決まらないので加えない｜体の大きさが撮影した人と違っても、向きだけを使うので崩れない。
- 2026-11-26｜同梱のサンプル｜`public/samples/` にスペアボディの男性・女性の GLB と、サンプルの動き（dizz-mocap-v1、機械的なダッシュ・その場、6秒）。開いたときは男性の体を読み込む｜ファイルがなくても試せるように。男性はユーザーの指示で実験用の既定。

- 2026-11-26｜サンプルの変更｜歩行・手振りを、前傾して腕と脚を一定周期で交互に動かす機械的なダッシュに変更。6秒・180コマ、180歩/分、その場でループ｜ユーザーが指定した二案からダッシュを採用。画面内で動きを見比べられるよう前進移動は加えない。

- 2026-11-26｜サンプル2種｜ダッシュの腕振り・腿上げを強め、240歩/分に加速。両手を差し込んで左右にこじ開ける6秒の動きを追加。「サンプル」を押すごとにダッシュとこじ開けを交互に読み込む。表示名は「サンプル」に統一｜ユーザーの指示。こじ開けは腕の長さを保ったまま手の軌道を作る。

- 2026-11-26｜第3のサンプル｜左右の手を胸の高さで交互に前方へ鋭く突き出し、引き戻す6秒の動きを追加。「サンプル」の巡回順をダッシュ→こじ開け→突き刺しに拡張｜ユーザーの指示。手先は前向きに揃え、片手を伸ばす間は反対の手を引いておく。

- 2026-11-26｜突き刺しの方向｜第3サンプルを、膝を曲げて前傾し、高い肘と下向きの手先から左右交互に腰より下へ刺し込む動きへ変更｜車の上から手を刺し込む、カマキリのような動きというユーザーの指定。

- 2026-11-26｜こじ開けの予備動作｜胸元で両手を合わせて一拍ため、約0.16秒で前方へ差し込んでから左右に開く。差し込みに合わせて体も前へ沈める｜ユーザーの指定した動作順と勢いを表現するため。

- 2026-11-26｜男性サンプルの外観｜身長1.88mを維持し、肩幅・胴周径・腕脚周径を減らした細身の男性GLBへ差し替え。色はシルバー、metallic 0.55・roughness 0.32。`_src/scripts/male-sample.mjs`でスペアボディの生成処理を再利用して作成｜ユーザーの指定。骨格とメッシュを同じ体型から生成し、動きを適用できる状態を保つ。

- 2026-11-26｜環境反射｜男性の金属材質に、Three.js同梱のRoomEnvironmentからMac上で生成した環境マップを適用。PMREMは初回のみ生成し再利用、反射強度0.85｜男性サンプルに環境反射を追加する指示。外部HDR画像の取得なしで、周囲の部屋と照明の映り込みを表現する。

- 2026-11-26｜背景とグリッド｜男性サンプル選択時は黒背景にし、独立した「背景」選択で白・黒を切り替え可能にした。床と奥・側面の縦グリッドを表示し、背景に応じて線色を調整｜ユーザーの指定。

- 2026-11-26｜男女別ランダムサンプル｜「サンプル」をランダム選択に変更。男性は既存3種、女性はフラメンコ・サンバ・ヒップホップの各4秒の一振り。女性選択時は自動再生し、一振りで停止（くり返す操作で変更可）｜ユーザーの指定。ダンスも既存の関節JSON形式でMac上で生成する。

- 2026-11-26｜ゲームへの統合出力｜GLTFExporterで体・骨格・材質と現在の動きを1つのGLBへ統合。複製した骨格へローカル回転と位置を元fpsで焼き込み、速度・移動有無・ループ端点を反映。Three.js向けの読み込みコードも追加｜ユーザーが体とモーションを統合し、そのままWebゲームに導入することを指定。元JSONやリターゲット処理をゲーム側へ持ち込まず、標準のAnimationMixerで再生できるようにする。

- 2026-11-26｜柔らかさの利用｜スペアボディの柔らかさ・変位上限・減衰を読み、骨の加速度に対する減衰応答で揺らす。最大変位は柔らかさ適用済みとして使用。GLBへモーフアニメーションを焼き込み、元属性と設定も保持。ゼロ部分は標準sparseアクセサで保存｜ユーザーがスペアボディの追加出力を傀儡へ組み込むよう指定。Mac上で計算し、Three.js側の標準再生だけで揺れを再現できるようにする。

- 2026-11-26｜指モーションの統合｜hand-mocap-v1の左右別21点JSONを取り込み、手のひら座標へ変換して体の初期骨軸に合わせる。時間差と手首反映を左右別に指定でき、全身・指・柔らかさを同じGLBへ保存。指骨が不足する体ではデータを保持して保存を止める｜ユーザーの指定。スペアボディが手の改修中なので本体へは変更を入れず、同じ骨名・親子関係で接続できるようにする。
