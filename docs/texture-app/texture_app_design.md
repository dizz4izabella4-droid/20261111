# テクスチャ貼り付けアプリ 技術調査・設計書 v0.1

作成日: 2026-11-27 / 状態: 構想〜設計段階（実装前）

## 1. 目的と前提

- 3Dモデルにテクスチャを貼るブラウザアプリ。様々なモデル形式を読み込めること。
- 主な用途は人体モデル `spare_body.glb` に肌などを重ねて貼ること。このモデルは**骨格つき・UVなし**。
- 先に技術を調べてから設計する（本書の方針）。
- 成果はファイルで受け取る（pushなし）。

## 2. 技術調査の結果

### 2-1. 最大の論点は「UVなしモデルをどうするか」

テクスチャを貼るにはUV（モデル表面と画像の対応）が要る。UVなしモデルには**自動UV展開**が必要。

- 候補: **xatlas**（C++製UV展開をwasm化したもの）。three.js向けラッパー `xatlas-three`（npm、v0.2.0）がある。
- `xatlas-three` は `unwrapper.unwrap(geometry)` で `BufferGeometry` を展開する。生成UVは `uv`、元のUVは `uv2` に書かれる。
- 別実装 `xatlas-web` を使う例では、展開後に位置・法線・UV・indexを**新しい配列で作り直している**。つまり**頂点が複製・並べ替えされる**。

### 2-2. 骨格つきモデル特有のリスク（要検証）

UV展開は継ぎ目（シーム）で頂点を複製する。骨格つきモデルでは頂点ごとに `skinIndex` / `skinWeight` を持つので、**複製後の頂点に元の値を引き継がないと、動かしたときに崩れる**。

- xatlasは「新頂点 → 元頂点」の対応表（xref）を返せるので、これで `skinIndex` / `skinWeight` を再マップする方針。
- ただし `xatlas-three` が骨格属性を自動で引き継ぐかは、調査では確認できていない。**最初の検証項目**にする。引き継がないなら自前で再マップする（実装は小さい）。
- 同種の事例として、AOライトマップ焼きツールが「Skeletal Mesh support (Beta)」を掲げており、骨格つき+xatlasは実用例があるが、まだ発展途上の領域。

### 2-3. 貼り方の方式比較

| 方式 | 内容 | 骨格つきで | 判断 |
|---|---|---|---|
| A. UV展開 + テクスチャ合成 | UVを作り、キャンバスで合成した1枚を `map` に | 変形に追従する | **本命** |
| B. 投影 → UV空間へ焼き込み | 平面/箱/円筒から画像を投影し、結果をUVのテクスチャに描き込む | 追従する | Aの貼り付け方法として採用 |
| C. DecalGeometry | 貼る部分のポリゴンを切り出して別メッシュに | **追従しない**（スキニングされない） | 不採用 |

結論: **A + B**。見た目は「UVを作る → 投影やペイントでテクスチャ画像1枚に描き込む → モデルに貼る」。変形しても、書き出しても壊れにくい。

### 2-4. 読み込み形式

three.js標準ローダーで足りる。拡張子で振り分ける。

- glTF/GLB（`GLTFLoader`）、FBX（`FBXLoader`）、OBJ（`OBJLoader`）、PLY、STL など。
- PLY / STL は材質・UVを持たないことが多い → UV展開が必須になる。
- 読み込み後は全形式を共通の内部表現（Meshの配列）に正規化する。

### 2-5. 書き出し

- `GLTFExporter` で GLB 出力。テクスチャは埋め込み。骨格・アニメは維持される想定（検証項目）。
- 追加で、テクスチャ画像単体（PNG）とUVレイアウト画像も保存できるようにする。

### 2-6. 実装環境

- 既存作品に合わせて単一HTML構成を基本にする（three.js + importmap/CDN）。
- xatlasのwasmは外部配布（jsdelivr等）から読むため、**オンライン前提**。完全オフラインにするならwasmを同梱する。
- three.jsのバージョンは、`GLTFExporter` などアドオンを使うためES modules版（新しめ）を想定。旧r128固定の作品とは別系統になる点に注意。

## 3. 設計

### 3-1. 画面構成

- 中央: 3Dビュー（回転・拡大、骨格モデルはポーズなしで表示）
- 左: レイヤーパネル（ベース色／肌テクスチャ／部分貼り付けの追加・並べ替え・不透明度・ブレンド）
- 右: 選択中レイヤーの設定（投影方式、位置、スケール、回転）
- 下: UVプレビュー（展開結果の確認・トグル）
- 上: 読み込み / 書き出し

### 3-2. モジュール

1. **Loader**: 形式判別 → three.jsローダー → 内部Mesh配列
2. **UVManager**: UVの有無を判定。なければxatlasで展開し、骨格属性を再マップ
3. **LayerStack**: レイヤー管理（画像、色、投影設定）
4. **Baker**: 各レイヤーをUV空間のキャンバスに合成（解像度は1024〜4096を選択）
5. **Projector**: 平面・箱（トライプラナー）・円筒の投影を、UV空間に焼き込む
6. **Viewer**: three.jsの表示。合成キャンバスを `CanvasTexture` として `map` に設定
7. **Exporter**: GLB / PNG出力

### 3-3. データの流れ

読み込み → UVがなければ展開 → レイヤー追加・調整 → Bakerが1枚に合成 → Viewerに反映 → 書き出し

### 3-4. 人体モデル向けの特別な配慮

- **肌を全面に貼る**: 全身を1枚の肌テクスチャで覆うので、UV展開の結果（島の分割）が見た目に出る。シーム目立ちを抑えるため、展開時のチャート設定（分割の細かさ）を調整可能にする。
- **シーム補正**: UV島の境界で色がずれないよう、焼き込み時に島の外側へ数ピクセル色を広げる（dilation）。
- **重ね貼り**: 肌の上にほくろ・傷・日焼けなどを、投影＋不透明度で重ねる。
- **テクセル密度**: 顔など細部は密度を上げたいので、将来的に部位ごとの解像度重みづけを検討（v2以降）。

## 5. 未確認事項・リスク

1. `xatlas-three` が骨格属性（skinIndex/skinWeight）を引き継ぐか（M0で確認）。
2. `spare_body.glb` の頂点数。多すぎるとxatlasの展開に時間がかかる。実ファイルでの計測が必要。
3. 面の向きや法線が壊れているモデルでの展開品質。
4. 展開結果が「人が手で作ったUV」より分割が多くなる。見た目重視の用途では手作業UVより劣る可能性がある。
5. wasm外部読み込みのため、オフラインでは動かない（同梱で解決可能）。
6. `GLTFExporter` が骨格つきモデルのスキン・アニメを完全に維持するかの確認。
