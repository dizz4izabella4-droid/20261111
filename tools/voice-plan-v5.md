# 音声ツール 指示書 v5（自分の声の素材を録る → 組み替えて、テキストを話す）

作成: 2026-11-25 ／ 作成者: テッサ（考案・指示のみ。実装は Claude Code）
v4 からの変更: 中心を「セリフ1行ずつの録音」から「**音の素材（音節）を録り、組み替えて、入力したテキストを話す**」に変更。固定セリフの録音は「定型句」として残し、合成より優先する。

## 0. ねらい

自分の声で、**どんな日本語のテキストでも話せる**ようにする。
仕組みは「素材を録る → つなぎ合わせる」方式（連結合成）。声の自動合成 AI は使わない。
ツールは単一HTML・外部ライブラリなし（`tools/voice.html`）。処理はすべてブラウザ内で完結し、音声はどこにも送信しない。
特定のゲームを知らない。ゲームとの接点は §6 のパック形式だけにする。

**品質の見込み（先に正直に）**: 1音ずつ録ってつなぐ方式は、滑らかな自然音声にはならず、「少しカクつく、抑揚の平らな、手作り感のある声」になる。これを許容しつつ、(a) 録るときの声の高さ・長さをそろえる、(b) つなぎ目をなめらかにする、(c) よく使う言葉は丸ごと録って優先する、の3つで聞きやすさを上げる。

## 1. 確定事項

- 日本語のみ。自分の声。録音素材を組み替えてテキストを話すのが基本。
- 作り方は案B系（録音・切り分け・加工）。外部の合成エンジン・API は使わない。
- 女神への声づけはしない。ゲーム固有の仕様は持ち込まない。

## 2. 全体の流れ

**音源づくり**: 素材リストに沿って録音 → 自動で切り分け → 声の高さ・音量をそろえる → 試聴
**話す**: テキスト入力 → 読み（かな）に変換 → 音節に分解 → 素材をつなぐ → 再生
**書き出し**: 書き出しパック（セリフを話した音声）／音源パック（ゲーム内で話すための素材）
**導入**: リポジトリに置く → ゲームが読み込む → 確認

## 3. ツールの機能

### 3-1 音源づくり（素材の録音）

録る素材（約100）:
- 清音 46（あ〜ん）、濁音 20、半濁音 5、拗音 33（きゃ きゅ きょ …）。「を」は「お」と同じ音として扱い、別に録らない。
- 任意の追加: 外来音（ふぁ てぃ でぃ など）約20。
- 録らないもの: 促音「っ」は無音の処理、長音「ー」は直前の母音を伸ばす処理で作る（§3-5）。

録音の方法（まずは**単独音**。1音ずつ、同じ高さ・同じ長さで平らに言う）:
- 台本モード: 素材を行ごと（あ行、か行 …）に大きく表示。1行ぶんを、間を空けて続けて録る。
- **高さ・長さのそろえ補助**: 録音中に声の高さ（基本周波数、自己相関で推定）と長さを表示。基準の音（任意の高さを選んで鳴らせる）を聞いて合わせる。基準から外れた素材は警告。
- 録り直しは素材1個だけ。録音中は一定間隔で IndexedDB に退避（タブを閉じても復元）。
- 既存の音声ファイルの取り込みも同じ編集画面へ。
- 後の拡張（今回は作らない）: 連続音（「あいうえお」と続けて録って切る）モード。つなぎがより自然になる。

### 3-2 切り分け
- 波形（Canvas）と無音検出での自動分割。しきい値・最短無音・最短区間をスライダーで調整。
- 録った順に素材リストへ自動で割り当て。区切り線のドラッグ・追加・削除・結合、区間の試聴、割り当ての入れ替え。数が合わないときは不一致を表示。
- 前後の無音は、素材では**ほぼ詰める**（頭 5ms・尻 10ms ほど残す）。つなぐ前提のため、v4 の 30〜50ms より短くする。

### 3-3 素材の加工
- 低域カット（80Hz付近）、息・ポップの軽減、簡易ノイズゲート。
- **素材どうしの音量をそろえる**（実効値で）。ピーク ≤0.6。
- 頭と尻の短いフェード（2〜5ms）。つなぎ目のクリック音（プチ音）を防ぐ。
- 声の高さが基準からずれた素材の補正（ピッチ補正）は、**後回し**（PSOLA 等が必要で重いため）。まずは警告と録り直しで対応。
- 素材ごとの「トリム位置の微調整」と試聴。

### 3-4 テキスト → 読み（かな）
- 入力は**かな（ひらがな・カタカナ）が基本**。漢字の読みは、外部の辞書を使わない前提で次の方法にする:
  - 書き方: `暗算{あんざん}` のように、漢字の直後に読みを書く。
  - **ユーザー辞書**: 一度書いた読みは辞書に登録（JSON で読み書き）。次回から自動で当てる。
  - 読みが決まらない漢字が残っているときは、赤く表示して話さない（勝手に誤読しない）。
- 数字は規則で読みに変換（0〜99,999、小数点、「%」など最小限）。例: 12 → じゅうに。
- 助詞の読み: 「は」→「わ」、「へ」→「え」は自動変換しない。助詞は `[わ]` と書く、または辞書で登録（誤変換を避けるため）。
- 画面に「読み（かな）」と「音節の並び」を表示し、**手で直せる**。素材が無い音節は赤で表示。
- 句読点は間（、= 約 180ms、。= 約 350ms、？！= 約 350ms）に変換。

### 3-5 つなぎ方（合成）
- 並んだ音節の素材を、**短いクロスフェード（既定 12ms）で連結**。
- 速さ: 音節の頭・尻の重なりを増減して全体を速く／遅くする（声の高さは変えない）。
- 促音「っ」: 直前の素材の尻を短く切って、60〜90ms の無音を入れる。
- 長音「ー」: 直前の母音素材の後半を繰り返して伸ばす（クロスフェード）。長さは調整可。
- 撥音「ん」: 素材をそのまま使う（前後の影響は無視）。
- **最長一致優先**: 定型句（§3-6）に一致する言葉があれば、そちらを使い、残りを音節で補う。
- 調整項目: クロスフェードの長さ、速さ、音節間の間（ms）、全体のゲイン。
- 抑揚（高さの変化）は付けない（平らな声）。将来 PSOLA を導入する余地として、素材に基準の高さを記録しておく。

### 3-6 定型句（丸ごと録る）
- 台帳に「id / 文 / 読み / 状態」を持ち、よく使う言葉・名前・決めゼリフを**そのまま録る**（v4 の録音・切り分け・割り当てを流用）。
- 合成より自然に聞こえるので、**一致したら定型句を優先**する。
- 文のハッシュを保存し、文を直したら「差替待ち」と表示。

### 3-7 試聴
- テキストを入れて「話す」。再生しながら、いま鳴っている音節を強調表示。
- 定型句で鳴った部分と、音節でつないだ部分を色分け表示（どこが不自然かを見つけるため）。

## 4. 書き出し

目的が2つあるため、2種類に分ける。

**A. 書き出しパック（セリフを話した音声）** — v4 のボイスパックと同じ形式（§6-1）
- 台帳の各行（定型句、または合成した音声）を `voice.wav` ＋ `voice.json` にまとめる。
- ゲーム側は `play(id)` を呼ぶだけ。ゲームのセリフが決まっているときの標準にする。

**B. 音源パック（ゲーム内でその場で話す）** — 実装順の後半
- `voicebank.wav`（素材をつないだもの）＋ `voicebank.json`（音節ごとの開始位置・長さ・基準の高さ・定型句の一覧・辞書）＋ `speak-snippet.js`（合成を行うコード）。
- ゲーム内で `speak("…")` を呼ぶと、その場で素材をつないで話す。数字や名前が変わる文（例: 「ごじゅうのダメージ」）に向く。
- 読みの変換（§3-4）と合成（§3-5）の両方を含むため、スニペットは数百行になる。外部ライブラリなし。

どちらも容量の目安を書き出し前に表示（既定はモノラル・24kHz・16bit、約 48KB/秒。音源パックは素材約100個で約 1〜2MB）。mp3 等の圧縮は扱わない。

## 5. 動作環境の注意

- マイクは **https か localhost でのみ**使える。`file://` 直開きでは使えない可能性が高い。GitHub Pages 上か `python -m http.server` で確認。
- Claude のアーティファクト内ではマイクが使えない可能性が高い。録音は GitHub Pages 上の本体で行う。アーティファクトでは取り込み・加工・合成・試聴の確認まで。
- iPhone（Safari）は `MediaRecorder` の形式が異なる（mp4/aac）。`decodeAudioData` で読めることを確認。マイクが拒否されたときは、取り込みで続けられる案内を出す。

## 6. ゲームへの導入（ツールとゲームの約束事）

### 6-1 書き出しパックの形式（`format:1`、v4 から変更なし）

```
<ゲーム名>/voice/
  voice.wav     … 全行を1本につないだ音声
  voice.json    … 目次
```

```
{ "format":1, "name":"パック名", "version":"2026-11-25T21:40", "file":"voice.wav",
  "sampleRate":24000, "gain":1.0,
  "lines": { "boss.intro.1": {"start":0.000,"dur":1.820,"gain":1.0,"text":"…","hash":"…"} } }
```

- 行どうしの間に 0.1 秒の無音。`text`/`hash` で、文の変更を検出できる。

### 6-2 ゲーム側の再生コード（書き出しに添付）
- `voice.json` と `voice.wav` を `fetch` → `decodeAudioData` を**1回だけ**。`play(id)` は `start(0, start, dur)` で再生。出力は専用の `voiceGain` 経由。
- id が無い／未読み込み／OFF のときは `false` を返し、呼ぶ側は何もしない（文字だけが出る）。
- 同時に鳴らす声は1つ。新しい声は、前の声を 30ms でフェードアウトして切る。`stop()` あり。
- 自動再生の制限: 最初のタップの処理から `AudioContext.resume()`。読み込み失敗でゲームを止めない。
- 設定用に `setVolume(0〜1)`・`setEnabled(bool)`。BGM を下げたいゲーム向けに `onStart`/`onEnd`。

### 6-3 置く手順
1. ツールで書き出す（A: `voice.wav`/`voice.json`/再生コード。B: `voicebank.*`/`speak-snippet.js`）。
2. リポジトリの対象ゲームのフォルダに `voice/` を作って置く。
3. 初回のみ、コードをゲームに貼る（ゲームごとの組み込み指示書は、その都度テッサが作る）。
4. ゲームの文章表のキー＝ id にそろえ、セリフを出す箇所で `play(id)`（または `speak`）。**文字は常に出す。**
5. 更新は上書きだけ。`version` を `?v=` に付けて取得し、古い声が残らないようにする。

### 6-4 ゲーム内の確認
- `?debug=1` のときだけ、id を選んで再生できる一覧と、未収録の id の一覧。
- 確認: 声が遅れても先に文字が読める／声が重なっても前の声が切れる／声 OFF で完全な無音／最初のタップ前に呼んでも落ちない／再生が入力や描画を止めない。

### 6-5 文章の同期
- ゲームの文章表を JSON/CSV（`id,text`）で書き出す手段をゲーム側に用意し、台帳へ取り込む。台帳に無い id／ゲームに無い id／文が違う id を一覧表示する。
- 文を直したら該当行が「差替待ち」。再録（または再合成）→書き出しで、その行だけ更新できる。

## 7. 守ること

1. 単一HTML・外部ライブラリなし。API キー等は扱わない。音声を外部へ送らない。
2. 録音・取り込みは自分で用意した音のみ。
3. 音は耳で確認できないので、ピークと主要帯域の音量を数値で報告し、「耳での確認は未実施」と書く。聞きやすさの判断はユーザーが行う。
4. 作業ブランチ `voice-tool` に push。main へはユーザーの指示があるまで push しない。
5. ゲーム側への組み込みは、ツールとは**別のブランチ・別の指示書**で行う。

## 8. 実装順

1. 素材リスト（約100）と台帳（id 規則・JSON/CSV）、取り込み・波形表示・試聴
2. 切り分け（無音検出・手直し・素材への割り当て）
3. 素材の加工（音量そろえ・端のフェード・トリム微調整）と高さ測定の表示
4. **テキスト入力 → 読み → 音節 → 連結の合成と試聴**（まず取り込んだ音で成立させる）
5. 書き出しパック A（voice.wav/voice.json/再生コード）と容量表示 ← ここで試験ページ（`tools/voice-test.html`）で実際に鳴ることを確認
6. 録音（台本モード・レベルメーター・高さ補助・録り直し・IndexedDB 退避）
7. 定型句（最長一致優先）、ユーザー辞書、数字の読み
8. 音源パック B（`voicebank.*` ＋ `speak-snippet.js`）、ゲーム文章との同期

録音（6）は環境依存が大きいので、1〜5 は取り込んだ音で先に成立させる。

## 9. 検証

- 合成した音（WebAudio で生成した、音節の代わりのトーン）で、無音検出の区間数が正しい／素材を割り当て順どおりに取り出せる。
- 合成: 「あいう」を入力し、出力の長さ＝素材の長さの合計−クロスフェード分、になっていること。促音・長音・句読点の間が指定どおりであること。素材が無い音節は赤表示で、無音のまま進まず警告すること。
- 数字・助詞・漢字読み（`{}`・辞書）の変換の単体テスト（表で確認）。
- 加工後のピーク ≤0.6。つなぎ目のクリック音がない（つなぎ目前後の振幅差が閾値内）こと。
- 書き出した WAV を再読み込みして、`voice.json` の `start`/`dur` と長さが一致。試験ページで全 id を再生し、欠落しても落ちない（Playwright）。
- 疑似マイク（`--use-fake-device-for-media-stream`）で、録音→分割→割り当てが通ること。実機のマイクと聞きやすさはユーザー。
- 縦 390×780・横 1280×800 でコンソールエラー 0。タブを閉じて開き直したとき、IndexedDB から録音が復元できること。

## 10. やらないこと

声の自動合成・声質変換 AI・外部 API 連携。抑揚の自動付与とピッチ補正（後の拡張）。mp3 等のエンコード。特定ゲームへの組み込み（別指示書）。他人の声や権利のある音源の取り扱い。

## 11. 決定事項（2026-11-25「おまかせ」により、テッサが確定）

1. **録り方**: まず単独音（1音ずつ平らに録る）。聞こえが硬ければ、後で連続音モードを足す。
2. **漢字の読み**: かな入力＋`漢字{よみ}`＋ユーザー辞書。読みの自動判定は、外部辞書なしでは不可能なため行わない。
3. **ゲーム内で話す（音源パック B）**: 後回し。先にセリフの書き出し（A）まで作り、使ってみてから判断する。実装順 8 は、ユーザーの合図があるまで着手しない。
