# 3Dパーツ統合スタジオ — 引き継ぎメモ（別チャットで再開するときに最初に読む）

最終更新：2026-11-28

## これは何か

既存の製造アプリ4つ（**顔**＝`elena-head/`、**髪型**＝`hair-studio/`、**スペアボディ**＝`spare-body/`、**仕立て屋**＝`shitateya/`）で作った3D部品を読み込み、1体のキャラクターに**統合**する独立アプリ。
部品を読み込むと、頭・髪・衣服が身体に合う位置・大きさに**自動で**置かれ、必要なところだけ**数値・スライダー・3Dギズモ**で微調整し、**1つのGLB**に書き出す。プロジェクトの保存・復元もできる。

- 公開場所：`/20261111/parts-studio/`（3D制作カテゴリ `lab-3d` に登録。台帳は `data/works.json` の `parts-studio`）
- 既存4アプリは**変更していない**（製造専用のまま）。連携は「ファイルを読み込む」だけ。共有ストレージ等は前提にしていない。

## 座標とシーン階層

- スタジオの共通座標：メートル、+Y上、+Z正面、+X左、床 y=0。
- 各部品：`Part.root`（ユーザーが動かす変換）→ `normalize`（単位・向き）→ 読み込んだモデル（無改変）。
- 髪は顔の子（顔を動かすと髪も動く）。出力GLBでは顔・髪・通常配置の衣服を、対応する骨（head / chest / spine / hips）の子にできる（既定ON、見た目の位置は同じ）。

## 自動フィッティングの要点

- **顔→身体**：頭の高さ＝身体の頭の仮形状（なければ身長の1/7.5）を 身長/8.2〜身長/6.5 に収めた値。顔に首があれば、首の中心を身体の首の中心に、首の下端を身体の首の上端付近に重ねる。首が無ければ、あごの下の点を身体の首の上端に差し込む。
- **髪→顔**：髪と顔が同じ座標系（顔アプリの頭部モデルから作った髪）なら顔にそのまま重ねる。そうでなければ頭頂部と幅から等倍率で合わせ、補正が 0.4〜2.5倍を外れたら「要調整」。
- **衣服→身体**：骨名が身体と同じなら「骨に追従」（スケルトン・ウェイト維持）。骨が合わなければ無理に付け替えず、装着部位に合わせて等倍率で置く。
- 自動調整が怪しいときは確定せず「要調整」にして理由を表示。

## 重要な仕様判断（変えるときは注意）

- **骨追従中の衣服は位置・回転・スケールを変えても見た目が変わらない**（glTF のスキンはメッシュのノード変換を使わないため）。そのため調整欄を無効にして理由を表示し、「骨に追従」を外すと通常配置になる。
- **首の長さ・太さ**はメッシュの限定変形（首の管の頂点を横に拡縮／首より上を上下に移動）。スキンの重み・UV・頂点数は変えない。首を特定できない身体では「非対応」と表示。出力GLBには変形後の形が入る。
- **身体の頭の仮形状**（スペアボディは箱の頭）は、顔があると自動で隠す（三角形の索引を差し替えるだけ。元ファイルは変わらない）。出力GLBも同じ状態。「表示する」にも切り替えられる。
- 内部状態（元の頂点位置・索引）は `userData` に入れない（GLB出力に漏れるため）。`assembly-manager.ts` の `WeakMap`。
- 仕立て屋のGLBは「身体＋`cloth_*` 衣服」が1ファイル。身体が既にあれば衣服だけ取り込み、無ければ身体と衣服に分けて読み込む。身体は1体のみ（2体目は置き換え）。

## 既知の制限・未対応

- 髪型アプリ（`hair-studio/`）にGLB出力が**ない**（設定JSONのみ）。このアプリが読めるのはGLB/OBJなので、髪はそのままでは入らない。髪型アプリ側に「ポリゴン化したGLBを書き出す」機能を足すのが次の課題（`scripts/make-real-parts.mjs` の髪の部分が参考になる。ストランド式でポリゴンが非常に多い：既定で約230万三角形）。
- 髪は顔の座標系と一致しないとき、推定で合わせるだけ。前髪・後ろ髪の位置は目で確認する。
- 衣服の袖・裾・フィット量のメッシュ変形、体型が大きく違う身体への衣服のリターゲットは非対応（Transform調整のみ）。
- 詳細検査（貫通・浮き）は標本頂点と最寄り点の距離で、完全な接合の保証ではない。
- 確認済み（2026-11-28）：出力GLBを傀儡（`kugutsu/`）で開き、サンプルの動きで身体・衣服・頭・髪が動く（顔と髪は head の骨にぶら下がる）。
- 未確認：iPhone/Android 実機、Safari。
- 出力GLBを統合スタジオで開くと「身体＋他の部品を含む1体」として読み込まれる（部品ごとの再分解はしない）。
